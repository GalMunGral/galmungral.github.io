Beneath the Interface
界面之下

How exactly does a computer compute a vector-based graphical user interface into being? How do vivid visual metaphors arise algorithmically from the first principles of logic and arithmetic? This incomplete article is my first attempt to answer those questions as concisely and coherently as possible.

计算机究竟是如何通过“计算”让一个基于矢量的图形用户界面凭空产生出来的？生动的视觉隐喻，又是如何从逻辑与算术的第一性原理中，一步步以算法的方式浮现出来的？这篇（尚不完整的）文章，是我第一次尝试尽可能简洁地给出一个连贯的回答。

Event Loop
事件循环

The interactivity of a GUI comes from its event loop:

图形用户界面的交互性，来自于它的事件循环：

while !quit
  if event = poll(): handle(event) # input
  if dirty: draw()                 # output

In each iteration, the program processes inputs and generates outputs:

在每一次迭代中，程序都会处理输入并产生输出：

fn handle(event):
  target = pick(event.xy)      # <-- input, state
  target.handle(event)         # --> state

fn draw():
  for each geometry on screen: # <-- state
    draw(geometry)             # --> output, state

These two steps are interconnected like yin and yang — picking an event handling object selects a code path for program state updates and affects the geometries output by draw(). The updated arrangement of these geometries, in turn, dictates the behavior of pick(event.xy) in the next iteration.

这两个步骤如同阴阳一般相互关联：选中一个事件处理对象，会决定程序状态更新所走的代码路径，并进而影响 draw() 所输出的几何图形；而这些几何图形排列方式的更新，又反过来决定了下一次迭代中 pick(event.xy) 的行为。

Closed Curves
闭合曲线

At the core of 2D vector graphics is the mathematical concept of the interior of a closed curve, such as a circle or rectangle. We have all learned how to fill the interior of a rectangle with a nested loop:

二维矢量图形的核心，是“闭合曲线内部”这一数学概念，例如圆形和矩形。我们都学过如何用一个嵌套循环来填充矩形的内部： 

fn draw(rect):
  for y in rect.y1...rect.y2:
    for x in rect.x1...rect.x2:
      rect.color(x, y)

This idea can be generalized to all closed curves. The only difference is that the horizontal scan line at each \(y\) could potentially enter and leave the interior of the curve multiple times, resulting in multiple intervals to be filled:

这一思路可以推广到所有闭合曲线。唯一的区别在于，每条位于 \(y\) 处的水平扫描线，可能会多次进入和离开曲线的内部，从而产生多个需要填充的区间： 

fn draw(curve):
  for y in curve.y1...curve.y2:
    for x1, x2 in curve.intervals(y):
      for x in x1...x2:
        curve.color(x, y)

We can implement pick(event.xy) using the same logic: If a point at \((x,y)\) lies in the interior of a curve, \(x\) must fall within one of the horizontal intervals at \(y\), so there must be an odd number of intersections to either side along the \(x\)-axis. This hit-detection is known as the "even-odd rule". We could also apply the "non-zero winding rule", which I will not get into here.

我们可以用同样的逻辑来实现 pick(event.xy)：如果点 \((x,y)\) 位于曲线内部，那么 \(x\) 必定处于 \(y\) 处某个水平区间的中间，因此在 \(x\) 方向的两侧，交点的数量必定都是奇数。这种命中检测方法被称为“奇偶规则”。我们也可以采用“非零缠绕规则”，这里不作展开。

Polygons
多边形

How do we find curve.intervals(y) for an arbitrary parameterized closed curve? To answer this question, let's first look at a simple case: polygons. For polygons, our problem becomes much more tractable: We just need to find all line segments intersecting the scan line.

对于一条任意的参数化闭合曲线，我们要如何求出 curve.intervals(y) 呢？为了回答这个问题，我们先来看一个简单的情形：多边形。对于多边形而言，问题会变得容易处理得多：我们只需要找出所有与扫描线相交的线段即可。

Given a line segment between \((x_1,y_1)\) and \((x_2, y_2)\), where \(y_1 < y_2\), we know a scan line at \(y\) can only cross the line segment if \(y_1 \leq y < y_2\), in which case $$k=\frac{x_2-x_1}{y_2-y_1}, \quad intersection=\left(x_1 + k(y-y_1), y\right).$$

给定一条从 \((x_1,y_1)\) 到 \((x_2, y_2)\) 的线段，其中 \(y_1 < y_2\)，我们知道，只有当 \(y_1 \leq y < y_2\) 时，位于 \(y\) 处的扫描线才可能与该线段相交，此时 $$k=\frac{x_2-x_1}{y_2-y_1}, \quad intersection=\left(x_1 + k(y-y_1), y\right).$$

Here is the complete scan-line rasterization algorithm:

以下是完整的扫描线光栅化算法：

Keep track of the set of edges intersecting the scan line, along with their respective intersection points. In each iteration:
  1. Traverse each interval at current \(y\) and color each pixel.
  2. Increment \(y\), then:
    1. Discard edges that no longer intersect the scan line.
    2. Increment each intersection point \(p\) by \((k_p, 1)\).
    3. Add new edges that begin to intersect the scan line.
 维护一个与扫描线相交的边的集合，以及它们各自的交点。在每一次迭代中：
  1. 遍历当前 \(y\) 处的每个区间，并为每个像素上色。
  2. 将 \(y\) 加一，然后：
    1. 丢弃不再与扫描线相交的边。
    2. 将每个交点 \(p\) 按 \((k_p, 1)\) 递增。
    3. 加入新的、开始与扫描线相交的边。

Transformations
变换

To move and morph our polygons, we need to apply linear transformations. Since a polygon is defined by its vertices, we just need to transform each vertex before rasterization.

要移动和变形我们的多边形，需要用到线性变换。由于多边形是由其顶点定义的，我们只需要在光栅化之前对每个顶点进行变换即可。

Strictly speaking, the transformations are linear only if we use homogeneous coordinates \((wx, wy, w) \in \mathbb{RP}^2\) in the projective space to represent \((x,y) \in \mathbb{R}^2 \) in Euclidean space. The advantage of this framework is that 2D translation, rotation and scaling are all represented as composable \(3\times3\) matrices: $$T_{x,y} = \begin{pmatrix} 1 & 0 & x \\ 0 & 1 & y \\ 0 & 0 & 1 \end{pmatrix},\ R_{\theta} = \begin{pmatrix} \cos\theta & -\sin\theta & 0 \\ \sin\theta & \cos\theta & 0 \\ 0 & 0 & 1 \end{pmatrix},\ S_{c} = \begin{pmatrix} c & 0 & 0 \\ 0 & c & 0 \\ 0 & 0 & 1 \end{pmatrix}.$$ This is how CSS transform works under the hood.

严格来说，只有当我们使用射影空间中的齐次坐标 \((wx, wy, w) \in \mathbb{RP}^2\) 来表示欧几里得空间中的 \((x,y) \in \mathbb{R}^2 \) 时，这些变换才是线性的。这一框架的优势在于，二维的平移、旋转与缩放都可以表示为可以相互复合的 \(3\times3\) 矩阵：$$T_{x,y} = \begin{pmatrix} 1 & 0 & x \\ 0 & 1 & y \\ 0 & 0 & 1 \end{pmatrix},\ R_{\theta} = \begin{pmatrix} \cos\theta & -\sin\theta & 0 \\ \sin\theta & \cos\theta & 0 \\ 0 & 0 & 1 \end{pmatrix},\ S_{c} = \begin{pmatrix} c & 0 & 0 \\ 0 & c & 0 \\ 0 & 0 & 1 \end{pmatrix}.$$ 这正是 CSS 的 transform 属性在底层的工作原理。

Discretization
离散化

Now that we've handled the case of polygons, there is an obvious solution to finding curve.intervals(y): We can convert any curve into a polygon by discrete sampling! Increasing sampling rate would give us better results, and eventually a polygon would be indistinguishable from a smooth curve when line segments become subpixel.

既然我们已经处理好了多边形的情形，那么求 curve.intervals(y) 就有了一个显而易见的解法：我们可以通过离散采样，把任意曲线转换成一个多边形！提高采样率会带来更好的效果，而当线段的长度小于一个像素时，多边形最终将与光滑曲线无法区分。

Let's take elliptic arcs as a non-trivial example. Suppose we want to draw an arc from angle \(\phi_1\) to \(\phi_2\) on an ellipse with semi-major axis \(a\) and semi-minor axis \(b\), centered at \((x,y)\) and rotated by an angle \(\theta\). We can sample \(N + 1\) points: $$\Delta\phi = \frac{\phi_2 - \phi_1}{N}, \quad \begin{pmatrix}x_i\\y_i\end{pmatrix} = T_{x,y} R_{\theta} \begin{pmatrix}a\cos\left(\phi_1 + i\Delta\phi\right)\\ b\sin\left(\phi_1 + i\Delta\phi\right)\end{pmatrix}$$

我们以椭圆弧为例，来看一个不那么平凡的例子。假设我们想在一个半长轴为 \(a\)、半短轴为 \(b\)，中心位于 \((x,y)\)、旋转角度为 \(\theta\) 的椭圆上，画出一段从角度 \(\phi_1\) 到 \(\phi_2\) 的弧。我们可以采样 \(N + 1\) 个点：$$\Delta\phi = \frac{\phi_2 - \phi_1}{N}, \quad \begin{pmatrix}x_i\\y_i\end{pmatrix} = T_{x,y} R_{\theta} \begin{pmatrix}a\cos\left(\phi_1 + i\Delta\phi\right)\\ b\sin\left(\phi_1 + i\Delta\phi\right)\end{pmatrix}$$

You can smooth out this curve by increasing the sampling rate \(N\)!

Stroking
描边

Ellipses are not just interesting in their own right — thick curves, which are conceptually 1D but in fact 2D for practical purposes, could be rendered by drawing a sequence of skinny rectangles joined by circles, which are, of course, a special case of ellipses!

椭圆本身就很有意思，而且不止于此—粗曲线在概念上是一维的，但在实际渲染时其实是二维的，可以通过绘制一系列由圆形连接起来的细长矩形来实现，而圆形当然正是椭圆的一种特殊情形！

Color Gradients
颜色渐变

Before we transition to text rendering, let's take a brief detour and take a look at color gradients! Suppose we want the color to change from \(C_1\) to \(C_2\). All we need to do is to linearly interpolate — that is, calculate a weighted average of the two colors at each pixel: $$interpolate(C_1, C_2, t) = (1-t) \cdot C_1 + t \cdot C_2,$$ where the parameter \(t\) varies with some sort of distance metric across pixels.

在转向文本渲染之前，我们先绕个小道，来看看颜色渐变！假设我们希望颜色从 \(C_1\) 渐变到 \(C_2\)。我们需要做的，就是在每个像素处对这两种颜色做“线性插值”—也就是计算加权平均值：$$interpolate(C_1, C_2, t) = (1-t) \cdot C_1 + t \cdot C_2,$$ 其中参数 \(t\) 会随着像素间某种距离度量而变化。

Take a look at these examples: $$t_{radial} = \frac{\sqrt{(x-x_o)^2 + (y-y_o)^2}}{r}, \quad t_{linear} = \frac{y - y_{min}}{y_{max} - y_{min}}$$

Bézier Curves
贝塞尔曲线

Interestingly, applying linear interpolation on positions recursively based on the same \(t\) parameter at every level produces the so-called "Bézier curves".

有趣的是，如果在每一层都用同一个参数 \(t\)，递归地对位置进行线性插值，得到的正是所谓的“贝塞尔曲线”。

Given control points \(p^{(0)}_0, p^{(0)}_1, \dots p^{(0)}_n\), we could sample a Bézier curve \(B(t)\) at \(t\) iteratively using the De Casteljau's algorithm:

给定控制点 \(p^{(0)}_0, p^{(0)}_1, \dots p^{(0)}_n\)，我们可以用德卡斯特里奥算法，迭代地在参数 \(t\) 处采样贝塞尔曲线 \(B(t)\)：

In each iteration \(k \in [1, n]\), for each \(i \in [0, n - k]\): $$p^{(k)}_i = (1-t) \cdot p^{(k-1)}_i + t \cdot p^{(k-1)}_{i+1}$$ Finally, \(B(t) := p^{(n)}_0\) 在每一次迭代 \(k \in [1, n]\) 中，对每个 \(i \in [0, n - k]\)： $$p^{(k)}_i = (1-t) \cdot p^{(k-1)}_i + t \cdot p^{(k-1)}_{i+1}$$ 最终， \(B(t) := p^{(n)}_0\)

字体

In case you haven't guessed it by now, every single letter you are reading on this page at this moment — or indeed, any text that uses OpenType/TrueType fonts — is made of nothing but linear (line segments), quadratic and cubic Bézier curves!

如果你到现在还没猜到的话：此刻你在这个页面上读到的每一个字母—事实上，任何使用 OpenType / TrueType 字体的文本—都完全是由线性（线段）、二次和三次贝塞尔曲线构成的！

View Tree
视图树

Let's put everything together.

让我们把这一切整合起来。

A GUI mainly consists of a containment hierarchy of geometries, which are best represented as a tree. Visually, containers are placed beneath the things they contain, so nodes closer to the root must be drawn first. In other words, we should perform a pre-order traversal:

一个图形用户界面，主要由一套几何图形的包含层级构成，而这最适合用一棵树来表示。从视觉上看，容器总是位于其所包含之物的下方，因此越靠近根节点的节点，就必须越先被绘制。换句话说，我们应当执行一次前序遍历： 

fn drawView(parent):
  for curve in parent.curves:
    draw(curve)
  for child in parent.children:
    drawView(child)

Hit-detection is straightforward if we record the polygons in their draw order. We can simply do a linear search backwards for the last drawn — and therefore topmost — polygon containing the cursor position.

如果我们按照绘制顺序记录下这些多边形，命中检测就会变得很直接：我们只需从后向前做一次线性搜索，找到最后绘制—也就是最上层—的那个包含光标位置的多边形即可。

Alpha Blending
透明度混合

Within a view tree, geometries overlap and obscure each other. If for aesthetic reasons we want to see through a layer, we need to blend it with the underlying layers. To do so, instead of overwriting each pixel when drawing, we need to calculate a weighted average of the existing color \((r_2,g_2,b_2)\) at each pixel and the new color \((r_1,g_1,b_1)\) to be painted over it. The weight for each of the two colors is determined by its contribution to the alpha channel: $$a = a_1 + a_2 (1-a_1)$$ $$(r,g,b) = \frac{a_1}{a}(r_1,g_1,b_1) + \frac{a_2(1-a_1)}{a}(r_2,g_2,b_2)$$

在一棵视图树中，各个几何图形会相互重叠、相互遮挡。如果出于美观的考虑，我们希望能透过某一层看到下面的内容，就需要把它与下方的图层混合起来。要做到这一点，绘制时就不能直接覆盖每个像素，而要计算每个像素处已有颜色 \((r_2,g_2,b_2)\) 与将要叠加上去的新颜色 \((r_1,g_1,b_1)\) 的加权平均值。这两种颜色各自的权重，由它们对alpha 通道的贡献决定：$$a = a_1 + a_2 (1-a_1)$$ $$(r,g,b) = \frac{a_1}{a}(r_1,g_1,b_1) + \frac{a_2(1-a_1)}{a}(r_2,g_2,b_2)$$

This is known as the "over operator".

这被称为“over 运算符”。

Filtering
滤波

If we want to distinguish transparent layers more clearly, we could apply a blur post-processing effect. To do so, we need to convolve the image with a kernel — that sounds rather highbrow, but it just means a weighted average (again!) of the neighborhood around each pixel. The weights are given by a function \(G(u,v)\), called the kernel: $$C = \sum_{u=-k}^{k} \sum_{v=-k}^{k}G(u,v)$$ $$Output(x,y) = \frac{1}{C}\sum_{u=-k}^{k} \sum_{v=-k}^{k} G(u,v) \cdot Input(x-u, y-v).$$

如果我们想更清楚地区分各个透明图层，可以施加一种模糊的后处理效果。要做到这一点，需要用一个“核”对图像做“卷积”—这听起来很高深，但其实说的仍然是（再一次！）对每个像素周围邻域做加权平均。权重由一个称为“核”的函数 \(G(u,v)\) 给出：$$C = \sum_{u=-k}^{k} \sum_{v=-k}^{k}G(u,v)$$ $$Output(x,y) = \frac{1}{C}\sum_{u=-k}^{k} \sum_{v=-k}^{k} G(u,v) \cdot Input(x-u, y-v).$$

For blurring we usually use (a discrete version of) the 2D Gaussian function $$G(x,y) = \frac{1}{2\pi\sigma^2}\exp\left(-\frac{x^2+y^2}{2\sigma^2}\right).$$ This effect is called Gaussian blur.

做模糊处理时，我们通常使用（离散版本的）二维高斯函数 $$G(x,y) = \frac{1}{2\pi\sigma^2}\exp\left(-\frac{x^2+y^2}{2\sigma^2}\right).$$ 这种效果被称为“高斯模糊”。
